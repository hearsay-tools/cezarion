`acp-lifecycle.ndjson` is a **constructed, source/schema-derived** sequence,
not a captured model session. Text, paths, ids, tool arguments and outputs
are synthetic. Its expected events are hand-authored from the normalized
protocol contract, not generated by running the mapper.

The vendor source confirms streamed text/thoughts, pending/in-progress/
completed/failed tool updates, diff and location content, and Cursor task/
todo extensions. The standard `plan` frame is upstream-schema-derived;
this fixture does not claim that this Cursor version emits it in a live run.
The fixture's last line is the `session/prompt` response: the replay harness
calls `cursorTurnCompleted`, just as the runner does. Session creation is
runner-owned, so the replay sets `sessionId` and does not expect the mapper
to manufacture `session.started`.

The parent run's live probe observed **no usage events**, consistent with
this installed ACP implementation: the prompt result contains `stopReason`
only, and its ACP implementation has no usage/token telemetry publication.
No live-probe transcript is included here; none of these constructed frames
is labeled a live capture.

Although the public docs call task/todo extensions notifications, this
vendor version calls `connection.extMethod`, which calls `sendRequest`.
Thus the fixture carries JSON-RPC ids for those extensions. The runner must
acknowledge requests; the pure mapper accepts either request or notification
envelopes and never writes protocol replies.

## Telemetry limitation

Cursor's baseline fixture deliberately contains **no usage**. The two named
`CURSOR_NO_USAGE_TELEMETRY` exemptions in `ui-parity.test.ts` assert the
absence of both `usage.updated` and per-turn usage. Other backend assertions
remain unchanged.

The upstream ACP schema separately defines optional `usage_update` with
`used` (tokens currently in context), `size` (context capacity), and optional
cumulative `cost: {amount, currency}`. This is occupancy, not cumulative
session token consumption. The mapper deliberately emits no usage event
for this shape: `UiEvent` cannot represent occupancy alone, and inventing
zero directional counts would mislabel the snapshot as token spend. A
separate unit test pins this limitation. Directional usage stays absent
until the vendor reports telemetry compatible with the normalized contract.

Malformed plan/todo snapshots emit no events and preserve the existing dock,
including when only part of a snapshot is malformed. An explicitly empty,
valid array still clears the dock.

## Tasks and negotiated child sessions

`cursor/task` alone enriches the existing tool item with `toolKind: task`,
retaining its success/failure status. Its `agentId` is not proof of a child
transcript.

`acp-subagents.ndjson` is a separate **constructed, vendor-source-derived**
fixture, not a live capture. The installed `1699.index.js` subagent publisher
is enabled by client capability `_meta.subagents`. Its `announce` method
sends `subagent_spawned` on the parent session with `subagentSessionId`,
`name`, `task`, `capabilities`, and `_meta.cursor.toolCallId/agentId`.
Its per-child presenter then sends ordinary `session/update` frames with
the child session id. `sendState` reports `subagent_state_update` on the
parent session, including completed/failed/cancelled/disconnected states.
`resolveParentSession` also supports grandchildren.

The mapper records only announced child sessions, scopes their item ids,
and attributes their items through `parentItemId` to the spawning task.
Text buffers and tool maps remain independent between sessions. Child
terminal updates flush child text and settle the task, never the parent's
turn; only the parent's prompt response completes that turn. Child plans
and usage do not replace the parent's global panels. Unannounced session
frames and frames after child settlement are ignored. No child session is
inferred from an ordinary `cursor/task` frame.
