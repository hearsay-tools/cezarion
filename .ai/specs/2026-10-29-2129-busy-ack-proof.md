# Main CI busy-acknowledgement repair

Subject: hearsay-tools/cezarion#2129; diagnostic members
hearsay-tools/cezarion#2127 and hearsay-tools/cezarion#2128.

## Source and guarantee

`proof_base`: `e5619c08daf5d34b230bb25d04cd363ca46f4627`, also current main
at investigation time. GitHub API verified CI run 40833754496, attempt 1,
job 123313744743, step 9: push to main from `.github/workflows/ci.yml`.
U21t failed at `waits-parity-cells.testkit.ts:2402`: expected delivered false,
received true before releasing the native HTTP acknowledgement. The required
aggregate (job 123318187225, step 2) failed because `VITEST_RESULT=failure`;
typecheck, build/package and browser checks succeeded.

The load-bearing guarantee is unchanged: the marker's native turn can end while
its HTTP acknowledgement remains held, with only the existing completion wait
open. The explicit timer then retains its deadline and wakes exactly once beside
that completion wait. No existing assertion, deadline or timeout changes.

## Cause

OpenCode's native mock has separate handlers for a new prompt and input sent
into a busy turn. Only the new-prompt handler applied the configured delivery
control. Busy input bypassed it and returned HTTP 204 immediately. The CI state
dump shows extra conversation turns around marker admission and the marker echoed
as busy input. A controlled busy turn reproduces the exact U21t assertion.
This establishes the bypass mechanism; the original CI process is no longer
available to reconstruct every scheduling event.

The fix applies `delivery.ack` to the busy handler too, using the same original
and rewritten prompt text as the new-prompt handler. The existing optional steer
ACK delay still runs when the acknowledgement is released. SSE user messages,
consumption and turn-end remain independent of the HTTP acknowledgement.
Unconfigured mock execution takes the same immediate acknowledgement path.

## Failing-before / passing-after proof

A disposable checkout at `proof_base` used its own frozen-lockfile installation.
It ran no Squeal daemon. Commands ran under a 120-second process-group timeout
with a five-second SIGKILL grace.

First, the unchanged U21t cell passed alone and with two and six busy loops on
one allowed CPU. These passes do not establish a cause or a repair.

To force the busy ordering seen in CI, the disposable checkout alone inserted
these lines immediately before U21t's `u21t-marker-admission` checkpoint:

```typescript
const calls = store.readEvents(f.p.id).filter(event => event.type === 'tool-call').length;
await f.progress('mock:steer-tool');
await waitAt('busy-native-turn', () =>
  store.readEvents(f.p.id).filter(event => event.type === 'tool-call').length > calls);
```

The rest of the cell, including every assertion, stayed unchanged. This extra
worker update opens a native turn before the marker input, rather than relying
on contention to produce that order. The mock's existing 600 ms steer-tool turn
is only the scheduling probe; the committed regression uses a file gate instead.

```sh
timeout --kill-after=5s 120s npm test -- \
  packages/cezar/src/workflows/waits-opencode-workers-parity.test.ts \
  -t 'opencode U21t' --maxWorkers=1
```

Old mock: **1 failed, 48 skipped, 49 total**, at the same
`expect(delivered(f.p.id, markerId)).toBe(false)` assertion as CI.
Fixed mock: **1 passed, 48 skipped, 49 total**, including all remaining timer,
deadline and exactly-once assertions.

The new committed `native-delivery-control.test.ts` regression holds an opening
native turn behind `CEZ_MOCK_RELEASE_FILE`, waits for its recorded HTTP request,
then submits busy input. It waits for the mock's held signal or the actual ACK,
releases the opening turn, and asserts that the ACK remains pending through its
native turn-end. Both gates are released in cleanup. Host load cannot end the
opening turn before the busy input arrives.

Copy this test into the disposable checkout before applying the mock fix:

```sh
timeout --kill-after=5s 120s npm test -- \
  packages/cezar/src/core/native-delivery-control.test.ts \
  -t 'opencode holds a busy input acknowledgement' --maxWorkers=1
```

Old mock: **1 failed, 62 skipped, 63 total**, expected settled false, received
true. Fixed mock and the same file-gated test: **1 passed, 62 skipped, 63 total**.
The final combined proof ran both selections in one command:
**2 passed, 110 skipped, 112 total**. This is targeted evidence, not a full-suite pass.

## Default-path scope

This mock edit changes timing only when `CEZ_MOCK_DELIVERY_CONTROL` is configured
with a matching hold-ack control. Shipped dry-run scenarios do not configure that
control. Their frames and turn ends are unchanged, so this does not select browser
or packaged park fixtures under the dry-run reader-sweep rule. Existing shared
native delivery controls still cover every `RUNNER_IDS` backend; the new cell
covers OpenCode's additional busy HTTP handler. No runner implementation changes.
